# Checko API

REST API на PHP 8.3 без фреймворков. Сервис получает сведения об организациях и индивидуальных предпринимателях из [Checko](https://checko.ru): данные ЕГРЮЛ и ЕГРИП, бухгалтерскую отчётность и результаты поиска. Ответ источника сервис переводит в собственную модель. Поля получают латинские имена, вложенные блоки приходят к единому виду, коды строк отчётности становятся именованными показателями. Рентабельность, рост выручки и долговую нагрузку сервис считает сам.

В комплекте база данных SQLite (кэш, журналы, токены), Bearer-авторизация, документация OpenAPI со Swagger UI и веб-интерфейс для проверки контрагента.

## Быстрый старт

Нужен Docker.

```bash
docker compose up -d --build
```

| Что | Адрес |
|---|---|
| Интерфейс | http://localhost:8080 |
| Swagger UI | http://localhost:8080/docs/ |
| Спецификация OpenAPI | http://localhost:8080/openapi.yaml |
| Состояние сервиса | http://localhost:8080/health |

Токен для проверки: `demo-checko-api-token`. Контейнер записывает его в базу при старте.

**Демо-режим.** Без ключа Checko сервис отвечает настоящими ответами источника, которые я записал заранее, и помечает их заголовком `X-Data-Source: fixtures` и плашкой в интерфейсе. В записи есть ПАО Сбербанк (ИНН 7707083893), ООО «Яндекс» (ИНН 7736207543) и ИП Морозов А. С. (ИНН 402907671076). На другие идентификаторы сервис отвечает «не найдено», а поиск возвращает одну и ту же выдачу.

**Живой режим.** Checko выдаёт ключ бесплатно после регистрации на [checko.ru](https://checko.ru/integration/api), лимит составляет 100 запросов в сутки.

```bash
cp .env.example .env    # вписать CHECKO_API_KEY
docker compose up -d
```

Порт задаёт переменная `APP_PORT`: `APP_PORT=9000 docker compose up -d`.

### Примеры запросов

```bash
TOKEN=demo-checko-api-token

curl -H "Authorization: Bearer $TOKEN" http://localhost:8080/v1
curl -H "Authorization: Bearer $TOKEN" http://localhost:8080/v1/companies/7707083893
curl -H "Authorization: Bearer $TOKEN" http://localhost:8080/v1/companies/7736207543/finances
curl -H "Authorization: Bearer $TOKEN" "http://localhost:8080/v1/companies/7707083893/trademarks?page=2&limit=50"
curl -H "Authorization: Bearer $TOKEN" http://localhost:8080/v1/entrepreneurs/402907671076
curl -G -H "Authorization: Bearer $TOKEN" http://localhost:8080/v1/search \
     --data-urlencode "by=name" --data-urlencode "query=рога и копыта" --data-urlencode "limit=5"
```

Выпустить свой токен:

```bash
docker compose exec app php bin/console token:create "Отдел закупок" --limit=500
```

## Ресурсы

| Метод и путь | Ответ |
|---|---|
| `GET /v1` | список ресурсов |
| `GET /v1/companies/{id}` | карточка организации по ИНН (10 цифр) или ОГРН (13) |
| `GET /v1/companies/{id}/finances` | отчётность по годам с расчётными показателями |
| `GET /v1/companies/{id}/trademarks` | товарные знаки постранично |
| `GET /v1/companies/{id}/licenses` | лицензии |
| `GET /v1/companies/{id}/branches` | филиалы и представительства |
| `GET /v1/companies/{id}/founders` | учредители |
| `GET /v1/entrepreneurs/{id}` | карточка ИП по ИНН (12 цифр) или ОГРНИП (15) |
| `GET /v1/search?by=&query=&obj=&page=&limit=` | поиск по названию, ФИО, ОКВЭД, датам, телефону и почте |
| `GET /health` | доступность БД и расход суточной квоты источника, без токена |

У ресурсов `/v1` есть два флага. `raw=true` возвращает исходный ответ источника без служебного блока с балансом аккаунта, `refresh=true` обходит кэш.

Карточка приходит в виде `{data, links, meta}`. В `meta` лежат `cache` и `fetched_at`, у списков там же `pagination`. Подробные схемы есть в Swagger.

## Устройство

### Требования задания и классы

| Требование | Реализация |
|---|---|
| Класс для внешних запросов (точка доступа с ресурсами) | [`src/Http/Api.php`](src/Http/Api.php): единая входная точка. Класс регистрирует ресурсы и проводит запрос через цепочку middleware, а `GET /v1` отдаёт список этих ресурсов |
| Класс получения данных с целевого ресурса | [`src/Checko/CheckoApiClient.php`](src/Checko/CheckoApiClient.php): ключ, адрес метода, разбор ответа, распознавание «не найдено», перевод ошибок источника в исключения, проверка квоты |
| БД | SQLite через PDO: [`src/Persistence`](src/Persistence), схема в [`migrations/001_init.sql`](migrations/001_init.sql) |
| Токены доступа | [`src/Auth`](src/Auth): база хранит только SHA-256 токена, у каждого токена свой суточный лимит |
| Swagger | [`public/openapi.yaml`](public/openapi.yaml), Swagger UI лежит в [`public/docs`](public/docs) и работает без интернета |
| Свой интерфейс | [`public/index.html`](public/index.html), [`public/app.js`](public/app.js), [`public/app.css`](public/app.css) |

### Слои

```
Http         Api → Router → контроллеры; middleware: заголовки, журнал, ошибки, авторизация, лимит токена
  ↓
Checko       CachingCheckoClient → CheckoApiClient → мапперы ответа в доменные объекты
  ↓
Transport    RetryingHttpClient → RecordingHttpClient → CurlHttpClient

Domain       DTO и объекты-значения (ИНН, ОГРН, ОГРНИП, отчётность, поиск), без внешних зависимостей
Persistence  реализации интерфейсов кэша, токенов и журналов на SQLite
```

- `Transport` выполняет HTTP-запросы с повторами и ничего не знает о Checko. Тесты и демо-режим подставляют вместо него свой транспорт, остальной код при этом не меняется.
- Мапперы в `Checko/Mapping` знают русские ключи источника (`НаимПолн`, `Руковод`, `ОгрДоступ`). Доменные классы их не видят.
- Все зависимости собирает один файл, [`src/Bootstrap/Services.php`](src/Bootstrap/Services.php). Контейнера с автовайрингом нет, каждый `new` виден в этом файле.
- Код использует `declare(strict_types=1)`, `final` и `readonly` по умолчанию, перечисления для методов источника, строк отчётности и видов поиска.

## Особенности источника

Часть поведения Checko документация не описывает. Я выяснил его на живых ответах, записал все случаи в [`resources/fixtures/checko`](resources/fixtures/checko) и покрыл тестами.

- **«Не найдено» приходит со статусом успеха и списывает квоту.** На несуществующий ИНН источник отвечает HTTP 200, `meta.status: "ok"` и пустым `data`, а счётчик запросов растёт. Поэтому сервис проверяет контрольные числа ИНН, ОГРН и ОГРНИП до обращения к источнику: опечатка получает 422 и квоту не тратит. Пустой ответ сервис превращает в 404 и кэширует на час.
- **У каждого метода своя структура ответа.** Отчётность сообщает «не найдено» отсутствием блока `company`, пустой `data` значит другое. У банка `company` заполнен, а годовых данных нет. Сервис показывает это состоянием «отчётность не публикуется» и отвечает 200.
- **Отчётность приходит кодами строк** (`"2110": 544581317000`). Справочник итоговых строк форм по приказу Минфина № 66н лежит в [`ReportLine`](src/Domain/Finance/ReportLine.php), метрики сервис считает по нему. Если для метрики не хватает строки, она равна `null`, ноль сервис не подставляет. Расшифровку я сверил на данных: внеоборотные и оборотные активы в сумме дают баланс с точностью до рубля.
- **Закрытые сведения.** У части компаний реестр закрывает данные руководителей и учредителей: запись есть, флаг `ОгрДоступ` стоит, поля пустые. Сервис отдаёт такую запись с `access_restricted: true`.
- **Тяжёлые коллекции.** Ответ по ООО «Яндекс» весит 290 КБ, из них 1720 товарных знаков. Карточка содержит только размеры коллекций, записи отдают подресурсы. Подресурсы читают тот же закэшированный ответ и к источнику повторно не обращаются.
- **Общее число результатов поиска.** Документация о нём молчит, но в ответе есть поле `ЗапВсего`. Источник, судя по всему, ограничивает его числом 1000. API отдаёт значение как есть, интерфейс пишет «1000 и более».

## Ошибки

Ошибки приходят в формате `application/problem+json` по RFC 9457 с машиночитаемым полем `code`.

| Ситуация | Ответ |
|---|---|
| нет токена, токен неизвестен или отключён | 401 `UNAUTHORIZED` + `WWW-Authenticate` |
| исчерпан суточный лимит токена | 429 `TOKEN_LIMIT_EXCEEDED` + `Retry-After` |
| неверное контрольное число, формат, параметры поиска | 422 `INVALID_IDENTIFIER` или `INVALID_PARAMETER`, источник не вызывается |
| ИНН предпринимателя на ресурсе организаций и наоборот | 422 `WRONG_RESOURCE` с подсказкой нужного пути |
| источник ничего не нашёл | 404 `COMPANY_NOT_FOUND` или `ENTREPRENEUR_NOT_FOUND` |
| неизвестный маршрут, неверный метод | 404 `ROUTE_NOT_FOUND`, 405 `METHOD_NOT_ALLOWED` + `Allow` |
| исчерпана суточная квота источника | 503 `QUOTA_EXHAUSTED` + `Retry-After` до полуночи по Москве |
| источник ограничил частоту запросов (после повторов) | 503 `UPSTREAM_RATE_LIMITED` + `Retry-After` |
| источник не ответил вовремя (после повторов) | 504 `UPSTREAM_TIMEOUT` |
| источник ответил 5xx или недоступна сеть | 502 `UPSTREAM_UNAVAILABLE` |
| источник отверг ключ сервиса | 502 `UPSTREAM_AUTH_FAILED`: ключ принадлежит сервису, поэтому клиент получает 502 |
| источник вернул не JSON или неизвестную структуру | 502 `UPSTREAM_INVALID_RESPONSE` |
| источник отклонил параметры, которые собрал сервис | 500 `UPSTREAM_REJECTED_REQUEST`: ошибка на стороне сервиса, журнал получает запись уровня critical |

Сервис повторяет запрос до двух раз с экспоненциальной задержкой и случайным разбросом. Повтор работает для GET и только при 429, 5xx и сетевых сбоях, ошибки 4xx сервис не повторяет.

Если источник недоступен, а в кэше лежит устаревшая копия, сервис отдаёт её со статусом 200, заголовками `X-Cache: STALE` и `Warning: 110` и пишет предупреждение в журнал.

## Кэш, квота и журналы

| Ресурс | Срок жизни кэша |
|---|---|
| карточка организации и ИП | 24 часа |
| отчётность | 30 дней |
| поиск | 1 час |
| «не найдено» | 1 час |

Заголовок `X-Cache` показывает источник ответа: `HIT`, `MISS` или `STALE`. Ключи кэша разделены по режиму, так что демо-данные не попадут в живой режим, если вы потом добавите ключ.

Квоту сервис считает по счётчику самого источника, `meta.today_request_count`, и сохраняет его при каждом обращении. Когда счётчик доходит до лимита при нулевом балансе, сервис прекращает обращения до полуночи по Москве. Остаток квоты виден в `/health`.

Таблицы: `cache_entries`, `api_tokens`, `request_log` (входящие запросы, по ним считается лимит токена) и `upstream_calls` (обращения к источнику вместе с повторами). Журнал идёт в stderr контейнера строками JSON (`docker compose logs app`), ключ источника в нём заменён на `***`.

## Решения

**Почему официальное API.** Сайт checko.ru на запрос curl ответил 429 с первой попытки. Разметка страниц может поменяться в любой день, а API даёт ключ, бесплатный лимит и описанную структуру ответа.

**Почему SQLite.** Сервис работает в одном экземпляре, пишет в базу редко (только при промахе кэша) и держит короткие транзакции. Конкурентной записи с нескольких узлов, репликации и ролевого доступа задача не требует, а ради них обычно и берут сетевую СУБД. Доступ к базе закрыт интерфейсами (`CacheInterface`, `TokenStoreInterface`, `RequestLogInterface`, `UpstreamCallLogInterface`), поэтому для переезда хватит новой реализации `Persistence` и другого DSN. Из специфичного для SQLite поменяются прагмы в `Database::connect`, `AUTOINCREMENT` в схеме и синтаксис `ON CONFLICT` в кэше.

**Отложено.** Автоматический выключатель (circuit breaker) прекращает обращения к источнику после серии отказов. Ему нужно общее состояние между процессами php-fpm: ещё одна таблица или внешнее хранилище и собственный жизненный цикл. При лимите в 100 запросов в сутки и кэше с устаревшими копиями он даёт мало. Если нагрузка вырастет, это следующий шаг.

## Проверка качества

```bash
docker compose run --rm --no-deps app vendor/bin/phpunit
docker compose run --rm --no-deps app vendor/bin/phpstan analyse --memory-limit=1G
```

PHPUnit гоняет юнит-тесты (контрольные числа на реальных реквизитах, разбор всех ответов-ошибок источника, мапперы, расчёт метрик, кэш и устаревшие копии, повторы, квоту) и тесты уровня API. Тесты API проводят запрос через всё ядро и подменяют только сетевой транспорт. PHPStan работает на уровне 8.

Стиль кода соответствует PER-CS 2.0, конфиг лежит в [`.php-cs-fixer.dist.php`](.php-cs-fixer.dist.php). PHP-CS-Fixer в зависимости проекта не входит, проверка запускается разовым контейнером:

```bash
docker run --rm -v "$PWD":/app -w /app ghcr.io/php-cs-fixer/php-cs-fixer:3-php8.3 check
```

## Запуск без Docker

Понадобится PHP 8.3 с расширениями `curl`, `mbstring`, `pdo_sqlite`, `ctype` и `json`. Каталог `vendor` уже лежит в архиве.

```bash
php bin/console migrate
php bin/console token:seed-demo
php -S localhost:8080 -t public public/index.php
```

## Конфигурация

Сервис читает `.env`, а без него `.env.example`. Переменные окружения важнее обоих файлов.

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `CHECKO_API_KEY` | пусто | ключ источника; пустое значение включает демо-режим |
| `CHECKO_BASE_URL` | `https://api.checko.ru/v2` | адрес API источника |
| `CHECKO_TIMEOUT` | `10` | таймаут запроса к источнику в секундах |
| `CHECKO_DAILY_LIMIT` | `100` | бесплатный суточный лимит источника |
| `DATABASE_PATH` | `storage/database.sqlite` | файл базы |
| `LOG_STREAM` | `php://stderr` | куда писать журнал |
| `API_DEMO_TOKEN` | `demo-checko-api-token` | демо-токен, который контейнер создаёт при старте; пустое значение отключает его |
| `API_TOKEN_DAILY_LIMIT` | `1000` | суточный лимит нового токена |
